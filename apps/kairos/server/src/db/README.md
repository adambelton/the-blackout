# db/ — Postgres persistence

Drizzle-ORM over `postgres-js`, one Postgres database, owned entirely by Kairos. All durable state lives here; the runtime caches (the feed's in-memory entry list, the recent-cycles ring, the enrichment subjects in memory) are convenience layers *on top of* the DB — no state is held only in memory. Each broadcast's state is broadcast-scoped (cascades on delete); the only cross-broadcast tables are platform content (event profiles, service specs).

## What's here

- **`schema.ts`** — the table definitions + the pgEnum columns (values imported from `enums.ts` so the TS consts and the Postgres enums stay in sync by construction).
- **`enums.ts`** — the single source of truth for enum-like values that map to Postgres enum columns: `SERVICE_TYPES` (`enrichment`/`curation`/`generation`/`imagery` — the first two annotate / select per-cycle; the last two carry the prose generator's and the imagery selector's profile content, added 2026-05-14 with K6.1), `BROADCAST_STATUSES` (`pending`/`active`/`paused`/`complete` — `paused` is vestigial), `SPEC_STATUSES` (`experimental`/`active`/`archived`), `SOURCE_TYPES` (`event`/`moderator`/`narrative_context`/`narrative_voice`), `TRIGGER_REASONS` (`accumulation`/`external` — `improv`/`gap` were collapsed in). Each const array is paired with a derived string-union type + (where useful) a type-guard. Drift between an array and its pgEnum causes silent insert failures — change them together.
- **`client.ts`** — `sql` (the `postgres()` connection — Kairos's *only* pooled connection) and `db` (the Drizzle instance over it). Throws on startup if `DATABASE_URL` is unset.
- **`content-pool.ts`** — the **content-pool repository** (`content_pool_items` — pre-prepared tagged items the imagery selector picks from). Domain-agnostic: a prompt, a tag set, an opaque `consumer_metadata` blob the consumer threads a pointer into. Distinct from `client.ts`'s postgres connection pool — the file naming makes that explicit.
- **`broadcasts.ts`** — the broadcast / source / spec repository: `createBroadcastRow` (transactional — broadcast + sources + resolved specs), `getBroadcastWithConfig`, `listBroadcasts`, `updateBroadcast`, `deleteBroadcast`, source-management helpers, and `resolveSpecsForProfile` — the spec-precedence logic: per service in the profile, an explicit override version → the `active` spec → the `experimental` spec.
- **`migrate.ts`** — the programmatic migrator (`drizzle-orm/postgres-js/migrator`, not `drizzle-kit` — so the runtime image needs no devDeps and it runs in non-TTY shells). Idempotent. Run by Fly's `release_command`, the `predev` hook, and the test harness.
- **`check.ts`** — the post-migrate drift detector. Asserts three things and fails non-zero on any mismatch (`pnpm db:reset` is the pointer): every table defined in `schema.ts` exists in the DB, every applied-migration row's hash matches its journal entry by sha256, cursor count equals journal count. Wired into `predev` and `pretest` (after `migrate`); PR #45 wires it into Fly's `release_command` too. The structural enforcement that the rules-only discipline failed to provide — see the [`migrations` skill](../../../../../.claude/skills/migrations/SKILL.md) § Detection.
- **`reset.ts`** — the single sanctioned drift-recovery path: DROP SCHEMA `public` + `drizzle`, recreate, run `migrate`, run `seed`. **Local-only**, gated on a loopback hostname + "kairos" in the DB name — refuses on Neon / Fly hostnames. Use whenever `db:check` reports drift; surgical fixes (hand-INSERT'ing cursor rows, replaying SQL by hand, truncating `drizzle.__drizzle_migrations`) preserve invisible state and re-introduce drift later.
- **`seed.ts`** — upserts the `sporting_event` event profile (its `enrichment_services` list and `curation_service_tiers` `string[][]`) plus a placeholder `{ placeholder: true }` `experimental` spec per service. K6.2 + K6.3 also upsert **v1.0.0 `active`** rows for the surfaces whose original constants carried sport-specific content — read from `.md` files under `seed-data/sporting-event/` via `readFileSync`. Re-runnable (`onConflictDoNothing` on the unique key). Today's v1 rows: `generation`, `imagery`, `summary`, `momentum`, `tension_conflict`, `narrative_arc`.
- **`seed-data/sporting-event/`** — bootstrap-only content directory. Per-surface `.md` files that `seed.ts` reads to upsert v1.0.0 spec rows: `generation.md` / `imagery.md` / `summary.md` (narrative path, K6.2), `enrichment/<service>.md` + `curation/<service>.md` (per-service spec content, K6.3), `index.ts` files exporting the parsed shapes. Retires post-launch — once the admin app (`apps/kairos/client`, K6.3b) ships, the DB is the canonical source for any spec edit; this directory exists for fresh-DB bootstrap and git-history audit of "what v1 was." Tracked as a launch-checklist exit task in [`docs/prompts-as-content-design.md`](../../../../../docs/prompts-as-content-design.md) § *Source of truth for profile content*.

## The tables

| Table | Scope | What it holds |
|---|---|---|
| `event_profiles` | platform | The domain container — `name`, `description`, `enrichment_services: string[]`, `curation_service_tiers: string[][]`, `createdAt`/`updatedAt`. One row: `sporting_event`. |
| `service_specs` | platform | Versioned domain guidance per `(serviceName, eventProfileName, version)` — `status` (`experimental`/`active`/`archived`), `spec` jsonb, `activatedAt`/`archivedAt` (lifecycle), `createdAt`/`updatedAt` (row-audit; auto-bumps on UPDATE). Unique on the triple. |
| `broadcasts` | broadcast | `eventProfileName`, `status`, `specOverrides` jsonb, `config` jsonb (`{ generator: {...}, pipeline: {...} }`), `briefThreadInventory` jsonb (the `context_curator` activation extraction, persisted so a restart skips the Haiku call), `createdAt`/`updatedAt` (the `updatedAt` auto-bumps on UPDATE as of K6.1). |
| `sources` | broadcast | `name`, `type` (`SourceType`), `canonical` bool, `enrichmentTags: string[]` (service routing), `config` jsonb, `createdAt`. Cascades from `broadcasts`. |
| `feed_entries` | broadcast | Every ingested entry — `sourceId`, `timestamp`, `data` jsonb (consumer-defined), `enrichmentTags`. The replay / matchroom-bootstrap / post-restart-hydration record; **not** read for cycle batching (the waiting room is). |
| `generations` | broadcast | One per generated cycle — `triggeredAt`, `triggerReason`, `contextPackage` jsonb (the full assembly snapshot), `output` (prose), `wordCount`, `tokenUsage`, `durationMs`, `covers` jsonb. |
| `pipeline_cycles` | broadcast | One per flush (even skipped generations get a row, `generationId` null) — `triggeredAt`, `triggerReason`, `flushTrigger` (`cadence`/`closing`/`consumer_prompt`), `chunkEntries` / `annotations` / `curation` jsonb (the inspector's replay-grade snapshot), `timingMs` jsonb (per-stage wall-clock), `generationId` (FK, `set null` on generation delete). |
| `enrichment_service_states` | broadcast | One per `(broadcastId, serviceName)` — the three subject-state maps (`expressed`/`unexpressed`/`acknowledged`), `specVersion`, `lastSurfacedAt`, `updatedAt` (auto-bumps on UPDATE as of K6.1). Upserted after every cycle (and after the activation brief-init pass). |
| `content_pool_items` | broadcast | `prompt`, `tags: string[]`, `consumerMetadata` jsonb (opaque). The imagery selector reads these; the consumer pushes them via the pool endpoints. |
| `users` / `sessions` / `accounts` / `verifications` | admin-app | Better Auth's four tables, re-exported from [`@kairos/auth`](../../../../../packages/kairos/auth/README.md) so drizzle-kit picks them up via this server's standard `db:generate` flow (the admin app reads/writes but doesn't own the migration). `users` has no `role` column — Kairos has one user type. |

## How it fits

`client.ts`'s `db`/`sql` are imported wherever a query happens — `feed.ts`, `broadcast.ts`, `broadcast-health.ts`'s route, the `registry.ts`, `pipeline/pipeline.ts` (dynamic import for the cycle persist), `narrative/engine.ts`, the route modules. `auth.ts` (the admin Better Auth instance) builds a separate `postgres-js` client over the same `DATABASE_URL` — keeps the auth connection pool independent from the engine's. `enums.ts`'s types are imported widely (the source-type / broadcast-status / trigger-reason unions are part of several modules' contracts). `migrate.ts`, `check.ts`, `reset.ts`, `seed.ts` are standalone entry points. Migration discipline — generate structural DDL with `pnpm db:generate`, commit the SQL + `meta/_journal.json` + `meta/<idx>_snapshot.json` together, never hand-write structural DDL, never mix `db:push` and `db:migrate` on the same database — is the [root CLAUDE.md](../../../../../CLAUDE.md)'s / the [`migrations` skill](../../../../../.claude/skills/migrations/SKILL.md)'s, applied here unchanged. (The `drizzle/` directory holds five migrations as of K6.5+: `0000_fixed_synch.sql` (squashed baseline), `0001_flashy_umar.sql` (K6.1: `serviceType` enum gains `generation`/`imagery` + row-audit timestamps), `0002_aromatic_ulik.sql` (K6.2: `summary` service type), `0003_slim_sally_floyd.sql` (K6.3a: the four Better Auth tables), `0004_open_harrier.sql` (K6.5+: consolidate the per-service `generation`/`imagery`/`summary` `serviceType`s into one `narrative` stage-type — the one sanctioned exception to "never hand-write structural DDL": an enum-recreate whose `USING` remap drizzle-kit can't model, justified inline in the file per the escape-hatch rule). The architecture doc's references to `0006_…` etc. are stale numbers from before the squash.)

**Working looks like:** `[migrate] applying any pending migrations …` / `[migrate] done.` on startup; `[seed] sporting_event profile and placeholder specs created.` after a seed; `[feed] hydrated N entries for <id>` on runtime start; the `enrichment_service_states` rows updating every cycle so a conductor restart resumes mid-broadcast.

## Open work

- **`paused` is a vestigial `broadcast_status`** — no runtime path uses it; the real states are `pending` → `active` → `complete`. Either remove it (an enum-shrink migration — hand-written DDL) or document it as reserved.
- ~~**Row-audit timestamps are uneven.**~~ **Resolved 2026-05-14 by K6.1** (`0001_flashy_umar.sql`): `createdAt`/`updatedAt` added to `event_profiles` and `service_specs`; `createdAt` added to `sources`; `broadcasts.updatedAt` and `enrichment_service_states.updatedAt` switched to Drizzle's `.$onUpdate(() => new Date())` so they auto-bump on UPDATE (were `.defaultNow()` only — set on insert, not maintained).
