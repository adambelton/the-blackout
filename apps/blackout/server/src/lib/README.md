# lib/ — clients, the Kairos seam, distillation, calibration, views, auth

The server's library shelf — everything that isn't the conductor, the source adapters, the stream pipelines, the routes, or the WS handlers. It's a mix of three things: **external-service clients** (Kairos, Sportmonks, the TTS providers, Replicate, R2 storage, Anthropic, Deepgram is in `pipeline/`), the **distillation + event-correlation + calibration** machinery (the radio-commentary → structured-texture path), and **view builders + persistence helpers + auth + telemetry**. The unifying rule (the `blackout-server` skill's): server-side API clients live here, and *all* Kairos communication goes through `lib/kairos.ts` — no direct DB or internal imports across the module boundary.

## What's here, by area

### The Kairos seam
- **`kairos.ts`** — the typed HTTP/WS client. REST: `createBroadcast` / `getBroadcast` / `deleteBroadcast` / `activateBroadcast` / `completeBroadcast` / `pushEntry` / `sendFeedback` / `triggerNarrativeGeneration` / `getLatestTransitionEventType` / `listCycles` / `getCycle` / `getBroadcastHealth` / `getGeneration` / `listGenerations` / `listBroadcastEntries` / the content-pool CRUD (`listPoolItems` / `createPoolItem` / `updatePoolItem` / `deletePoolItem`) / `getHealth`. WS: `subscribeFeed(kairosBroadcastId, { onSync, onEntry, onNarrative, onImageryDecision, onGenerationSkipped, onClose })` → a `FeedSubscription` with `close()`. The Kairos-side types it speaks (`KairosBroadcast`, `KairosFeedEntry`, `KairosNarrativeOutput`, `KairosNarrativeImagery`, `KairosImageryDecision`, `KairosGenerationSkipped`, `KairosPoolItem`, `PacingSignal`). Auth: every request carries `Authorization: Bearer <KAIROS_API_KEY>`.
- **`kairos-bridge.ts`** — the per-broadcast lifecycle wrapper (the one place that ties Kairos's broadcast lifecycle to the Blackout's): `linkBroadcastToKairos` (create the Kairos broadcast with the seven sources — `matchEvents` canonical, `matchPressure`/`matchStats`/`matchAction` non-canonical, `moderator`, `narrativeContext`, `narrativeVoice` — seed the brief + author voice, persist `kairosBroadcastId`; idempotent), `activateBroadcast` (flip Blackout → `live` + Kairos → `active` (seeds voice/context; throws if the author brief is empty — Kairos rejects activation without `narrative_voice` content), seed the lineups block, set the roster, start the runner, ensure the conductor), `completeBroadcast` (flip both → complete, stop the runner, stop the conductor, clear the roster), `signalFor(wpm)` + `reportPacing(broadcastId, words, seconds)` (map a clip's words/seconds to a `slow_down`/`speed_up`/`on_track` signal + send it). Re-exports `SOURCE` from `@blackout/shared`.
- **`kairos-heartbeat.ts`** — pings the feed WS every 15s, terminates on missed pong (Kairos restarts under `tsx watch` leave consumer sockets half-open; TCP keepalive alone takes minutes).

### Distillation, correlation, calibration (the radio-commentary path)
- **`distiller.ts`** — `distillCommentary(chunk)` — one Haiku call per buffered chunk of raw transcription lines. Emits three classes: `atmosphere` (crowd/manager/ambient — non-event observations the commentator reports from what they directly saw, written first-person, kept even when it sounds like opinion if structured data can't capture it), `event_texture` (build-up/reactions/body-language *around* a canonical event — carries an optional `eventHint` so the correlator can link it to the Sportmonks row), `event_claim` (structured signal that commentary noticed an event happen — internal-only, never reaches Kairos; used for offset calibration + releasing buffered texture with `parentSourceId`). Deliberately drops: pure opinions, opinions redundant with structured data ("Brighton are dominating" — we have pressure data), speculation, broadcast-level editorial framing, the fact-claim of an event when emitting texture (the Sportmonks row is canonical for that). `EVENT_CLAIM_CLASSES` is the extension point for new event coverage.
- **`distillation-buffer.ts`** — `CommentaryDistillationBuffer` — accumulates utterances, flushes through the distiller on a 12s timer or reactively when `flush()` is called (the runner calls it before processing a Sportmonks canonical event, so leading-up commentary makes it into the correlator before the event does). Sequential flushes (a flush in flight blocks the next; lines that arrive during a flush are caught by the next — never lost). Routes the three classes via the callbacks the runner installs.
- **`event-correlation.ts`** — pure rules (no I/O) for matching the distiller's `event_claim` / `event_texture` against canonical Sportmonks events. Three ledgers (owned by the runner): canonical events seen recently (the matchable targets), pending claims, pending texture. `resolveCanonical` (a canonical lands → match pending claims/textures, release matched textures with `parentSourceId`, emit a calibration sample), `findCanonicalForLateArrival` (a claim/texture lands → match an already-seen canonical), `pruneExpired` (window-expiry sweep — pending textures aged out get released as standalone `match_action` *without* the unverified `eventClass` tag (the "Euler Brand finished cleanly" fictional-equaliser fix); pending claims aged out are dropped — no-match telemetry). `surnameKey` / `teamKey` (the matching keys), `CORRELATION_WINDOW_MS` (90s; `VAR_CORRELATION_WINDOW_MS` 120s — VAR leads the structured row by a lot). `EventClass` is the canonical-event-class union.
- **`canonical-event-ingest.ts`** — the pure orchestrator for "a Sportmonks event arrived": flush distiller → build canonical → `resolveCanonical` → release matched textures → emit calibration → `normaliseEventNames` → push canonical. Pinned by tests so the runner's wrapper just wires its mutable state in.
- **`canonical-ledger-seed.ts`** — `buildCanonicalLedgerSeed(existingKairosEntries, broadcastId)` — rebuild the correlator's canonical ledger from existing Kairos `match_events` entries on a runner restart (without it, every restart starts the correlator empty and commentary claims for already-happened events expire without matching — the "[correlation] N claim(s) expired" log spam).
- **`effective-offset.ts`** — the audio→canonical effective-offset state helper. `applyCalibrationSample(currentOffset, rawDeltaSeconds)` — the single canonical EWMA update (α=0.3, clamped 0–120s; Δ>0 → shrink, Δ<0 → grow). All offset mutations go through this (the dead-loop bug — calibration samples recorded but never read — was structurally possible because read and write weren't tied; routing all mutations here makes the next regression noisy). Lives in its own file so the formula is unit-testable without the runner's DB/Kairos/conductor graph.
- **`name-normalise.ts`** — `normaliseTranscript(text, roster)` / `normalisePlayerName(name, roster)` — reconcile ASR garbles and short-form references to canonical roster spellings before text reaches the distiller (or before event payload names reach Kairos, so enrichment services see stable subject ids). No-op when the roster is empty (pre-lineup-publication activations).

### Views & persistence helpers
- **`broadcasts.ts`** — the broadcasts-table repo (`listBroadcasts` / `getBroadcast` / `createBroadcast` / `updateBroadcast` / `deleteBroadcast`).
- **`broadcast-transitions.ts`** — the Blackout-side lifecycle transition validity (`draft → scheduled → live → complete → archived`).
- **`broadcast-view.ts`** + **`broadcast-view-logic.ts`** — `buildBroadcastView(broadcast)` — the matchroom/replay bootstrap DTO: the broadcast row, the persisted narrations with their bundles + resolved storage URLs, the revealed/guarded event sets (`computeGuardedEntryIds` — a canonical event card stays hidden only while a narration that *covers* it is mid-flight, visible by default otherwise — the opt-out reveal contract), the inferred phase (`inferPhaseFromStatus`), the archive shape on `complete`. The pure logic (guard computation, phase inference, `parseContentTime`) is in `-logic.ts` for testability.
- **`moderator-view.ts`** — `buildModeratorView(broadcast)` — the moderator-console bootstrap: the historical feed entries reshaped via `toFeedEntry` (the same rules the live moderator WS uses), service status, etc.
- **`rehydration.ts`** — `rehydrateLiveBroadcasts({listBroadcasts, ensureRoomConductor, isBroadcastRunnerActive, startBroadcastRunner})` — on server restart, re-create the conductor + runner for every broadcast still marked `live`. Pure-ish (deps injected) so it's testable.
- **`runner-shutdown.ts`** — `stopRunnerIdsForShutdown(ids, stopBroadcastRunner)` — the process-shutdown contract: never mark a broadcast `complete` on the way out (a `tsx watch` restart / a SIGTERM during a deploy is *not* a match-end signal — the bug that flipped a live broadcast to complete mid-FA-Cup-SF). Extracted so the contract is unit-testable.
- **`roster-registry.ts`** — in-memory per-broadcast roster (home/away player lists + team names), set at activation from the lineups, read by `name-normalise` + the distiller's context provider.
- **`lineups.ts`** — `fetchLineupsBlock(fixtureId)` — pull the starting XIs from Sportmonks, format them into the brief block seeded as part of `narrative_context`.
- **`illustration-pool.ts`** — server-side helpers for the studio's illustration-pool prep (the pool items the Kairos imagery selector picks from; the bytes live in `broadcast_illustrations`, pool membership is authoritatively on the Kairos side via `content_pool_items` with the `illustrationId` stashed on `consumer_metadata`).
- **`prompt-suggester.ts`** — `suggestPrompts(...)` — Anthropic call that suggests illustration prompts for the studio, with previously-discarded prompts fed in as negative context.
- **`tag-deriver.ts`** — `deriveTags(prompt)` — derive the tag set for a pool item from its prompt.
- **`tts-voices.ts`** — the admin-curated TTS-voice-catalogue repo (`listTtsVoices` / `getTtsVoice` / `createTtsVoice` / `updateTtsVoice` / `deleteTtsVoice`; the `isDefault` voice is stamped onto new broadcasts).
- **`radio-sources.ts`** — the radio-source-catalogue repo (`listSources` / `getSourceById` / `createSource` / `updateSource` / `deleteSource` / `recordObservation` — the latter feeds the per-source observed-offset stats from calibration samples).
- **`users.ts`** — `listUsers` / `setUserRole` (admin user management).
- **`canonical-compose.ts`** is in `conductor/`, not here — it's conductor-internal.

### External-service clients & infra
- **`tts/`** — the TTS provider abstraction. `types.ts` (`TtsProvider` union, `TTS_PROVIDERS`), `index.ts` (`generate(provider, text, voiceId, speed?)` → audio bytes; `listAllVoices` / `listProviders`), `openai.ts` / `elevenlabs.ts` / `hume.ts` (the implementations — ElevenLabs is the production default; OpenAI/Hume are pluggable). The conductor's `synthesiser.ts` calls `generate`.
- **`storage/`** — the asset-store abstraction. `types.ts` defines `StorageProvider`; `index.ts` selects R2 whenever R2 credentials are configured; `r2.ts` provides Cloudflare R2 public or presigned URLs; `memory.ts` is the test/isolated fallback served by `routes/storage.ts`. Normal development uses the `blackout-dev` R2 bucket, not process memory.
- **`sportmonks.ts`** — the Sportmonks HTTP client + fixture/period/participant types + `mapEventType`. **`sportmonks-types.ts`** — the type-id reference cache (`loadSportmonksTypes` warmed at server startup, `getTypeRef`). Consumed by `sources/sportmonks.ts`.
- **`replicate.ts`** — `generateImage(prompt)` → `{ bytes, contentType, model, generationMs }` (the illustration generator; the conductor and the studio both call it).
- **`anthropic.ts`** — `getAnthropicClient()` — the shared Anthropic SDK client for the server's own Haiku calls (the distiller, the prompt-suggester). (Distinct from Kairos's `llm/anthropic.ts` — different process, not shared code; Kairos has no published-package consumer.)
- **`content-time.ts`** — the period→content-time math (the Blackout-owned content-time vocabulary): `formatContentTime`, `computeLiveContentTime`, `computePhaseAnchor`, `wallClockForMatchMinute`, the `MatchPhase` / `PhaseAnchor` types. Consumed by `sources/sportmonks.ts` and exposed by `SportmonksEventSource` for the runner's stamping.
- **`defaults.ts`** — the consumer-side prompt constants (`DEFAULT_NARRATIVE_VOICE`, `HALFTIME_REFLECTION_PROMPT`, `CLOSING_PASSAGE_PROMPT`, `CLOSING_CYCLE_PROMPT`) — the prose the conductor splices into Kairos's `consumerPrompt` for the explicit halftime/closing generations and the closing-cycle framing. *(These live on the Blackout side precisely because Kairos's enum stays domain-agnostic — "halftime reflection" is football vocabulary; the consumer owns the wording.)*
- **`auth.ts`** — server-side Better Auth, session **validation only** (email/password sessions are issued by the web; this instance reads them and omits the user-create hook). **`auth-middleware.ts`** — the Hono `authContext` middleware (validates the session cookie on every request, attaches `user`+`session`), `requireAuth`, `requireRole("admin"|"writer")`.
- **`services.ts`** — `checkServices()` — probe Sportmonks / Deepgram / Kairos reachability for the moderator WS connect message + the broadcasts-page poll.
- **`telemetry.ts`** — the PostHog wrapper (`captureEvent`, `captureInvariant`, `flushTelemetry`) — mirrors Kairos's telemetry shape so one dashboard pivots on `service`.

## How it fits

`lib/` is the dependency floor for the rest of `apps/blackout/server`: `conductor/` imports the Kairos client, TTS, storage, replicate, tts-voices, kairos-bridge, defaults, telemetry, canonical-compose (its own); `lib/broadcast-runner.ts` imports the Kairos client/bridge, the Sportmonks source, the distillation + correlation + calibration files, `name-normalise`, `roster-registry`, `radio-sources`, the conductor registry (for `getRoomConductor`); `routes/` import the broadcasts/tts-voices/radio-sources/users repos + the view builders + the Kairos client (inspector proxies); `ws/` import the runner relays + the conductor registry + `services` + the feed-shape mappers; `src/index.ts` imports the rehydration + the runner registry + the conductor registry + the auth middleware + `sportmonks-types` warm. Dependency flows are mostly one-way *into* `lib/`, with a couple of deliberate back-references the comments flag (the runner ↔ kairos-bridge ↔ conductor-registry triangle is broken with dynamic imports where it would be circular).

## Contract

### Provided
- The Kairos client surface (`lib/kairos.ts`) and the lifecycle bridge (`lib/kairos-bridge.ts`) — **the only sanctioned way to talk to Kairos**. The distillation/correlation/calibration primitives (`distillCommentary`, `CommentaryDistillationBuffer`, `resolveCanonical` / `findCanonicalForLateArrival` / `pruneExpired`, `applyCalibrationSample`, `buildCanonicalLedgerSeed`). The view builders (`buildBroadcastView`, `buildModeratorView`). The repos (broadcasts, tts-voices, radio-sources, users). The clients (`tts/generate`, `getStorage`, `generateImage`, `getAnthropicClient`, `createSportmonksClient`). The auth middleware (`authContext`, `requireAuth`, `requireRole`). The prompt constants (`defaults.ts`). The content-time math (`content-time.ts`).
- The contract that *all* Kairos comms route through `lib/kairos.ts` — a route handler or the conductor calling Kairos's HTTP directly, or importing a Kairos internal, is a seam violation.

### Depended on
- **From Kairos:** the REST + WS surface in [`apps/kairos/server/README.md`](../../../kairos/README.md) — `lib/kairos.ts` is the typed mirror of it. `KAIROS_URL` + `KAIROS_API_KEY` env.
- **From `@blackout/shared`:** `SOURCE` (the source-name constants), `Broadcast` / `RadioSource` / `TeamSide` / `MatchEvent` / the bundle types / `parseContentTime` etc.
- **From `@blackout/auth`:** `createAuth` + the auth schema (the shared Better Auth factory — `lib/auth.ts` instantiates it in validation-only mode).
- **External:** Anthropic SDK (distiller + prompt-suggester), Deepgram SDK (used in `pipeline/`, key passed from here), the TTS providers' APIs, Replicate, Cloudflare R2, Sportmonks. Env: `KAIROS_URL`, `KAIROS_API_KEY`, `ANTHROPIC_API_KEY`, `DEEPGRAM_API_KEY`, `SPORTMONKS_API_TOKEN`, `REPLICATE_API_TOKEN`, the TTS provider keys, the R2 creds, `DATABASE_URL`, `BETTER_AUTH_SECRET`, `ALLOWED_ORIGINS`, `POSTHOG_KEY`/`POSTHOG_HOST` — validated in `env.ts` (live-broadcast subset via `assertLiveBroadcastEnv`).

## Open work

- **`broadcast-runner.ts` is a 1073-line god-file** (it lives in `lib/` but is the source-capture orchestrator) — candidate splits: a `SourceCapture` layer, a `CorrelationLedger` wrapper, the calibration loop. Needs an end-to-end conductor smoke + kairos-bridge tests first. Tracked server-wide in [`../../README.md`](../../README.md).
- **`distiller` event-class tags are unverified until correlated** — uncorrelated `event_texture` is demoted to plain `atmosphere` on the prune sweep (30s), not immediately; uncorrelated claims are just dropped. Per-event-class correlation windows + per-class radio-offset profiles are MVP tuning.
- **`lib/` is a flat shelf of ~40 files** mixing clients, business logic, and helpers — `tts/` and `storage/` already have sub-dirs; the distillation/correlation/calibration cluster (`distiller` / `distillation-buffer` / `event-correlation` / `canonical-event-ingest` / `canonical-ledger-seed` / `effective-offset` / `name-normalise`) is arguably its own `lib/distillation/` sub-module, as is the Kairos seam (`kairos` / `kairos-bridge` / `kairos-heartbeat`). No work pending; noted as a candidate refactor if the shelf keeps growing.
