# conductor/ — the room conductor

The per-broadcast machine that turns Kairos's narrative stream into the live experience: subscribes to Kairos's feed, runs the broadcast-phase FSM, synthesises each narrative to audio, generates/resolves an illustration, composes the per-passage canonical bundle the matchroom walks, schedules playback by `setTimeout`, and fans cues to every subscribed WS client. **The server-side `setTimeout` keyed on clip duration is the authoritative clock — clients react.** Exactly one `RoomConductor` per broadcast; lifecycle tied to broadcast activation/completion.

For where this sits, the pipeline diagram, and the cue vocabulary, see [`../../README.md`](../../README.md). This README goes one level deeper.

## What it does

### `RoomConductor.ts` — the conductor

- **`start()`** — recover the phase from Kairos's latest transition entry (so a conductor coming up against a broadcast already past kickoff doesn't restart at `warming` and re-push every transition); recover the running canonical state by folding every persisted `broadcast_narrations.revealingCanonical` forward (`recoverRunningCanonical`); open the Kairos feed subscription (`kairos.subscribeFeed`) with handlers for `onSync` / `onEntry` (→ `cacheEntry` + `maybeTransitionFromEntry` + fan out `feed_entry`), `onNarrative` (→ `onKairosNarrative`), `onImageryDecision` (→ `handleImageryDecision` — early-fire so Replicate runs in parallel with the still-pending Sonnet), `onGenerationSkipped` (→ fan out), `onClose`.
- **`cacheEntry(entry)`** — LRU insert into the 500-entry `entryCache` (the entries the domain-aware invariants look up by id), then `maybeTransitionFromEntry` → `nextPhaseFromEntryPhase(data.phase, this.phase)` → `transitionTo(next)` if it advances. This is the *single* source for phase transitions in both live (the runner pushes a synthetic whistle entry → round-trips through Kairos → lands here) and replay (the entries already exist in Kairos, arrive on sync). `transitionTo` is idempotent on same phase and rejects backward transitions by ordinal.
- **`transitionTo(phase)`** — fan out a `phase` cue; on `complete`, fan out `broadcast_status_changed` (the matchroom flips into replay mode, refetches `GET /broadcasts/:id`). Side-effects: `halftime` → one `triggerExplicitGeneration(HALFTIME_REFLECTION_PROMPT)`; `full_time_winddown` → open the closing-passage protection window (`fullTimeObservedAtMs` + a `CLOSING_DEADLINE_MS` (300s) timer → `onClosingDeadlineElapsed`, which force-completes iff the conductor is fully idle), then `triggerExplicitGeneration(CLOSING_PASSAGE_PROMPT)`. `triggerExplicitGeneration` is fire-and-forget — the narrative lands on the feed WS the conductor already subscribes to, flows through the normal synthesis+play path; the consumer-side prompt is spliced verbatim, Kairos's enum stays domain-agnostic.
- **`onKairosNarrative(narrative)`** — `checkNarrativeInvariants` (domain-aware postconditions, see below); `composePassageBundle` (build `revealedCanonical` = snapshot of running state, `revealingCanonical` = the deltas this passage will reveal during audio) → fold `revealingCanonical` forward into `runningCanonical` via `applyRevealingCanonical` (the chain invariant — folded at *compose* time, not synthesis success or audio start, so a synthesis failure still folds the reveals forward and the next passage's `revealedCanonical` absorbs them); update `lastEmittedContentMinute` (the monotonic floor on the emitted content minute); fan out `narrative` (text propagation — UI renders prose whether or not audio is on) + (if `narrative.imagery`) the imagery fallback path; if `ttsEnabled !== true`, stop here; else enqueue `{ narrativeId, text, … , revealedCanonical, revealingCanonical }` and fan out `passage_added`, then `drainSynthesisQueue()`.
- **`drainSynthesisQueue()`** — serial (Kairos's emission order must be preserved; synthesis is 2–3s and parallel would risk reordering): for each queued narrative, `resolveTtsVoice` → `synthesiseNarration` → fan out `passage_audio_ready` → `onNarrationReady` → if nothing playing, `startPlayback`; else push to `readyQueue` + `sendPreload`. On synthesis failure: fan out `passage_skipped` (running canonical state already advanced at compose time — reveals not lost).
- **`startPlayback(narration)`** — set `playbackStartedAt` (persisted), `currentlyPlaying`; fan out `play` (legacy) + `passage_started` (bundle); `setTimeout(onClipEnd, durationMs + INTER_CLIP_GAP_MS)` (400ms gap absorbs client network+decode jitter so the next `play` doesn't clip the previous audio's tail).
- **`onClipEnd(finished)`** — `reportPacing(broadcastId, wordCount, playbackSeconds)` to Kairos (fire-and-forget — sizes the next cycle's word target); `decideClipEndAction` (pure decider in `phase-logic.ts`): `advance_queue` (normal — pull the next clip or wait), `wait_for_closing_passage` (winddown, queue empty, but the closing roundtrip hasn't completed and the deadline hasn't passed — hold the broadcast alive; Finding 7, 2026-05-03 debrief), `complete_broadcast` (winddown, queue empty, deadline reached, no in-flight work, sane match age), `suppress_winddown_complete` (same shape but match too young to plausibly be at FT — < 60min — almost always a transient phase glitch; leave phase at winddown). On `complete_broadcast`/the deadline path, `transitionTo("complete")` + `completeBroadcast(broadcastId)` via `kairos-bridge`.
- **`handleImageryDecision(narrativeId, imagery)`** — deduped by `narrativeId` (whichever of the early `imagery_decision` or the later `narrative.imagery` arrives first wins). `hold` → no-op; `pool` → `resolvePoolIllustration` (look up the bytes by the `illustrationId` Blackout stashed on `consumerMetadata` when the studio pushed the item to Kairos → fan out `illustration` + `passage_updated`); `generate` → `generateIllustration` (Replicate, parallel with synthesis → persist `broadcast_illustrations` + storage bytes → fan out). Failures are telemetry-only — the previous image stays.
- **`addClient(ws, transform?)`** — register a WS client, send the `connected` snapshot (`currentPlay` + the bundle `currentPassage`, both with `serverNow` refreshed so every client computes the same audio offset), return the unsubscribe fn. The `transform` lets the calling WS handler reshape cues for its audience (matchroom whitelists + reshapes; moderator forwards nearly everything; returning `null` drops the cue).
- **`fanOut(cue)`** — to every subscribed client, via each client's transform; drop a client on send failure. `broadcastCue(LatencySampleCue)` — the runner's surface for runner-side observations that need the moderator UI but don't originate from the Kairos feed.

### `RoomRegistry.ts` — the process-wide map

`ensureRoomConductor(id)` → create+start the conductor if the broadcast is `live` and `kairosBroadcastId`-linked (returns null otherwise; finalises a stale `live` broadcast with an hours-old FULL_TIME entry instead of respawning — the condensed-replay case). `getRoomConductor` (no create), `stopRoomConductor`, `stopAllRoomConductors` (server shutdown), `listRoomConductors`. The registry intentionally creates a conductor with zero clients — the playback clock is owned by the server, not by any viewer; narratives are synthesised and advanced whether or not anyone's tuned in.

### `synthesiser.ts` — narrative → audio artefact

`synthesiseNarration({ broadcastId, narrativeId, text, provider, voiceId, speed, batchEntryIds, covers, contentTime, revealedCanonical, revealingCanonical })` → TTS via `lib/tts` → measure the MP3 duration by parsing the headers (`music-metadata` — the providers don't reliably return duration, and a wrong duration means the scheduler drops trailing audio or leaves gaps) → if the clip's wpm is below `MIN_CLIP_WPM` (90 — catches Hume outlier clips with long non-speech padding), resynthesise once → persist a `broadcast_narrations` row (audio key = `broadcasts/<id>/narrations/<narrativeId>.mp3`, one artefact per Kairos narrative; the row carries `batchEntryIds` + `covers` for the reveal contract + the per-passage `revealedCanonical`/`revealingCanonical` bundle, written together) → write the bytes to storage → return the `NarrationRecord`.

### `canonical-compose.ts` — the matchroom bundle (Design A)

`toCanonicalEvent(entry)` projects a Kairos `match_events` entry into the matchroom-shaped `CanonicalEvent` (drops pressure/zone noise types and non-`match_events` sources; strict `eventType` union). `composeRevealingCanonical({covers, batchEntryIds, entryCache})` builds the per-passage revealing-canonical — each cover with a `charOffset` → an event marker at that offset (early reveal mid-audio); each cover without → an audio-end-fallback marker; each `batchEntryId` not in covers → an audio-end-fallback marker (preserves the "in batch but not cited" reveal contract). `composeContentMinute(batchEntryIds, entryCache, monotonicFloor)` picks the matchroom's content-minute label — the earliest subject time among the batch, clamped up to the floor so the consumer's content clock can't regress (mirror of Kairos's `clampMonotonicMinute` — both must clamp because `play.contentTime` (Kairos-clamped, numeric) and `revealedCanonical.contentMinute` (server-composed, string) are separate channels emitting the same content-time value — see [`../../../../docs/vocabulary.md`](../../../../docs/vocabulary.md) § Time). `composePassageBundle({runningCanonical, phase, covers, batchEntryIds, entryCache, lastEmittedContentMinute})` → `{ revealedCanonical, revealingCanonical }` — `revealedCanonical.phase` from `runningCanonical.phase` (the listener's view, lagging the FSM `phase`); `revealingCanonical.phase` set when the FSM phase has advanced past `runningCanonical.phase`, with the charOffset from the cover for the synthetic phase-transition entry the prose cites (audio-end fallback if not cited) — that's how the listener's phase view stays anchored to audio playback rather than wall-clock.

### `phase-logic.ts` — the pure phase rules

Extracted so the decision surface is testable without a real conductor. `DATA_PHASE_TO_BROADCAST_PHASE` (`first_half`→`live_first_half`, etc.), `PHASE_ORDINAL` (the monotonic progression), `PHASE_FOR_TRANSITION_EVENT` (the reverse map — recover phase from a transition entry), `TRANSITION_FOR_PHASE` (what synthetic `match_events` entry the runner pushes per phase whistle — `eventType`/`content`/`subjectTime` (subject-time string)/`phase`, plus `closingExtensionSeconds=15` + `closingPrompt` on HALFTIME/FULL_TIME so post-whistle texture lands in the closing cycle), `nextPhaseFromEntryPhase`, `shouldSuppressWinddownComplete` (the 60-min match-age guard), `decideClipEndAction` (the four-outcome decider above), `decideSourcePushAllowed` (subject-phase-driven: live phases open; post-whistle ≤ `POST_WHISTLE_TEXTURE_WINDOW_SECONDS` (15) → closing-window texture; `pre_match` + `match_action` → warming-window atmosphere; else closed; ambient seed sources always open). `CLOSING_DEADLINE_MS` (300s — the give-up fallback for when Kairos errors mid-roundtrip).

### `invariants.ts` — domain-aware postconditions

Football-specific runtime checks on a narrative arriving from Kairos against the cached batch entries: `event_uncovered` (a `GOAL`/`OWN_GOAL`/`PENALTY`/`RED_CARD`/`SECOND_YELLOW`/`VAR`/`VAR_CARD` entry was in the generator's context but wasn't cited — the "full time, a draw at 3-0" smoking gun), `score_phrase_without_goal` (the prose has a score-like phrase but no `GOAL`-family entry in covers — narrowed to assertion-strength patterns after the FA Cup SF retro showed the broad patterns false-firing on legitimate prose about past goals / scoring droughts; the oblique-hallucination class is caught by `event_uncovered` instead). Warn-only, log + PostHog. The domain-agnostic counterpart is Kairos's `invariants.ts` — the split keeps the module boundary (Kairos doesn't know football).

### `index.ts`, `types.ts`

`index.ts` re-exports `RoomConductor` + the registry functions + the cue types. `types.ts` declares `NarrationRecord` and the `ConductorCue` union (legacy playback cues + the bundle cues sourced from `@blackout/shared` + the operator-only `feed_entry`/`latency_sample`) — the runtime semantics of `BroadcastPhase` and the gameplay transitions live here even though the types themselves are in `@blackout/shared` (so the inspector/admin UIs can switch on them).

## How it fits

- **Upstream:** `RoomRegistry.ensureRoomConductor` is called by `kairos-bridge.activateBroadcast`, by `rehydrateLiveBroadcasts` on server restart, and by the matchroom/moderator WS handlers on first subscribe. The conductor subscribes to Kairos's feed WS via `lib/kairos.subscribeFeed`.
- **Downstream:** synthesises via `lib/tts`, generates illustrations via `lib/replicate`, persists to `db/` (`broadcast_narrations`, `broadcast_illustrations`), stores bytes via `lib/storage`, reads TTS voices via `lib/tts-voices`, reports pacing + completes via `lib/kairos-bridge`, fans cues to the WS clients the matchroom/moderator handlers register (via the matchroom transform / passthrough).
- **The runner side:** the broadcast-runner pushes synthetic phase-transition entries to Kairos (the conductor observes them on its feed sub — same path as replay) and calls `getRoomConductor(id)?.broadcastCue(latency_sample)` + `getRoomConductor(id)?.canPushFromSource(...)`.

## Contract

### Provided
- `ensureRoomConductor(id)` / `getRoomConductor(id)` / `stopRoomConductor(id)` / `stopAllRoomConductors()` / `listRoomConductors()`; `conductor.start()` / `stop()` / `refreshBroadcast(b)` / `getSubjectPhase()` / `canPushFromSource(sourceType, data)` / `addClient(ws, transform?)` / `broadcastCue(latency_sample)`.
- The cue vocabulary (`ConductorCue` — see [`../../README.md`](../../README.md)): the playback contract (`connected`/`narrative`/`preload`/`play`/`phase`/`illustration`), the bundle contract (`passage_added`/`passage_audio_ready`/`passage_started`/`passage_skipped`/`passage_updated`/`broadcast_status_changed`), the operator cues (`feed_entry`/`latency_sample`). The chain invariant on the bundle (`revealedCanonical[N+1] === apply(revealedCanonical[N], revealingCanonical[N])`). The clock contract: clients compute audio offset from `(serverNow − playbackStartedAt)` on every `play` and on `connected.currentPlay`/`currentPassage`.
- The pure deciders (`decideClipEndAction`, `decideSourcePushAllowed`, `nextPhaseFromEntryPhase`, `shouldSuppressWinddownComplete`) and the maps (`PHASE_FOR_TRANSITION_EVENT`, `TRANSITION_FOR_PHASE`, etc.) — used by the runner and unit-testable in isolation.

### Depended on
- **From Kairos (via `lib/kairos`):** `subscribeFeed` (`onSync`/`onEntry`/`onNarrative`/`onImageryDecision`/`onGenerationSkipped`/`onClose`); `KairosNarrativeOutput` (text, `covers` with `charOffset`, `batchEntryIds`, `contentTime`, `imagery`); `getLatestTransitionEventType` (phase recovery); `triggerNarrativeGeneration` (explicit halftime/closing generations). The contract is: one `narrative` per generated cycle, `covers` ⊆ `batchEntryIds`, `contentTime` monotonic, `imagery` advisory.
- **From `@blackout/shared`:** `Broadcast` / `Passage` / `CanonicalState` / `RevealingCanonical` / `CanonicalEvent` / `TeamSide` / `BroadcastPhase` and the helpers `applyRevealingCanonical` / `emptyCanonicalState` / `parseMatchTime` / `SOURCE`. The bundle cues are typed from here so server and web share the wire shape.
- **From `lib/`:** `tts`, `replicate`, `storage`, `tts-voices`, `kairos-bridge` (`reportPacing`, `completeBroadcast`), `defaults` (the prompt constants), `telemetry`.
- **From `db/`:** `broadcast_narrations` (write the row + the bundle + `playbackStartedAt`; read for recovery), `broadcast_illustrations` (write generated, read pool).

## What working looks like

`[conductor:<id>] started (kairos=<id>, tts=on)`; per cycle: `narrative` → (only at whistles) `[conductor:<id>] phase X → Y` → synthesis (2–3s, serial, `narration_synthesised`/`narration_play_started` telemetry) → `play`/`passage_started` → `setTimeout(onClipEnd)` → `onClipEnd` → `reportPacing`. The matchroom reveals in step with the narrator's audio; nothing visible before it's been spoken. No `event_uncovered`/`score_phrase_without_goal` warnings in the logs/PostHog (occasional are tolerated; a run is a regression). On a server restart mid-broadcast, `recoverRunningCanonical` rebuilds the bundle state from persisted narrations and the phase recovers from Kairos's latest transition — playback resumes where it left off.

## Anti-patterns

- **No prose generation here.** The conductor synthesises, schedules, composes bundles, fans out — it never writes narrative. (`triggerExplicitGeneration` asks *Kairos* for a passage; it doesn't generate one.)
- **No second clock.** The server's `setTimeout(onClipEnd, durationMs)` is the authority. Clients seek to `(serverNow − playbackStartedAt)`; they never run their own timeline.
- **Fold reveals at compose time, not at audio start.** A synthesis failure must still fold the passage's `revealingCanonical` forward so the next passage's `revealedCanonical` absorbs the events — never let a failed clip swallow a goal.
- **Audio is canonical.** Nothing visible (text, events, score, illustration) before the narrator has spoken it. The bundle's reveal markers + the matchroom transform whitelist enforce this; operator-only cues (`feed_entry`, `latency_sample`) never reach the matchroom.
- **No backward phase transitions.** `nextPhaseFromEntryPhase` / `transitionTo` reject them by ordinal — a re-cached or late-arriving earlier-phase entry is safe.
